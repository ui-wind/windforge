# Windforge Reference Sources

## Primary references

### Uniwind

- https://docs.uniwind.dev/pro-version
- https://docs.uniwind.dev/pro/compatibility
- https://docs.uniwind.dev/pro/reanimated-animations
- https://docs.uniwind.dev/api/css
- https://docs.uniwind.dev/migration-from-nativewind
- https://docs.uniwind.dev/pro/changelog
- https://github.com/uni-stack/uniwind

Use Uniwind primarily to study:

- Tailwind v4 integration
- CSS parser behavior
- className mapping
- Pro native engine behavior
- ShadowTree update model
- Reanimated className animation
- native theme transitions
- group variants
- native metrics
- performance benchmark methodology

### NativeWind

- https://www.nativewind.dev/docs
- https://www.nativewind.dev/v5
- https://www.nativewind.dev/docs/core-concepts/tailwindcss
- https://www.nativewind.dev/docs/core-concepts/states
- https://www.nativewind.dev/docs/tailwind/transitions-animation/animation
- https://www.nativewind.dev/v5/core-concepts/functions-and-directives
- https://github.com/nativewind/nativewind
- https://www.npmjs.com/package/react-native-css-interop

Use NativeWind primarily to study:

- Tailwind language integration
- build-time compilation
- CSS interoperability
- platform differences
- state/pseudo variants
- CSS variables
- Tailwind v4 directives
- React Native Web behavior
- Metro integration
- prop remapping

## Important research principle

These sources define reference behavior, not Windforge implementation.

Windforge should reproduce useful public behavior through its own architecture.
